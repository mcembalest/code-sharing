The data

What the system has access to

The source is a single 233 MB PDF: roughly 20 years of the publication, 5,117 pages. The letters are chart-heavy, so extracting the written text alone would miss most of the quantitative content. The system therefore captures both the prose and a description of every chart. The unit of retrieval and citation is the individual page; 235 pages that are purely legal disclaimers are excluded, leaving 4,882 indexed pages.

Preparation

How the archive was indexed (done once, offline)

Before any question is asked, the archive is processed once into a searchable index. The time-consuming work happens here so that answering a query later is fast.

1

Extract & clean

Each page's text is extracted; running headers, repeated legal disclaimers, and footers are removed, and each page is assigned its publication date.

5,117 clean page records
2

Describe every chart

A vision model (Google Gemini Flash) reads each chart-bearing page image and writes a precise prose description — titles, axes, data series, and the specific figures — so that visual content becomes searchable text.

~2,300 chart descriptions
3

Build a topic map

Topic phrases are extracted from each page and normalized into a consistent taxonomy — 14 high-level themes and 3,933 specific topics. This collapses 20 years of shifting terminology (for example, “solar cost” in 2005 and “module ASP / LCOE” in 2025) into a single topic, so coverage can be measured.

14 themes · 3,933 topics
4

Construct the search index

Each page's combined text (prose + chart description + topics) is turned into two complementary search structures:

Keyword search

Matches exact words and phrases — precise for names, tickers, and specific terminology.

Meaning-based search

Captures what each page is about, so a question matches the relevant pages even when they use different words than the question does.

At query time

How a question is answered

When you submit a question, the agent runs a short, transparent research loop rather than a single lookup:

1

Classify the question

The agent first determines the type of question — a narrow factual lookup, a broad “everything about X” survey, or an analytical question — and matches its effort to that type.

2

Search the archive

It draws on three complementary methods: exact-mention search for named entities and phrases; combined keyword + meaning search for broader recall; and topic enumeration, which pulls every page tagged to the relevant topics for exhaustive coverage.

3

Rank & filter

Candidate pages are ranked by relevance to the question. A calibrated threshold separates pages that are genuinely on point from those only loosely related, which are summarized rather than quoted.

4

Read & gather evidence

The agent reads the strongest pages in full and collects the supporting quotes and charts, recording which search produced each one.

5

Synthesize a cited answer

It writes a direct answer with inline page citations, repeating the search-and-read steps until the evidence is sufficient — then stops.

The interface

What you see, and why

The interface is built for verification. The report presents the answer first, followed by findings grouped by theme: the most directly relevant (“primary”) findings are shown in full, and supporting ones are collapsed. A separate agent trace records every search the agent ran and every step it took — full transparency into how the answer was produced. Every [p. N] citation is a link: clicking it opens the actual page from the PDF, within its full issue, so any claim can be checked at the source.
